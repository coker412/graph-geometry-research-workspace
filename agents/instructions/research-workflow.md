# 数学研究工作流

本文件适用于文献核查、问题形成、证明搜索、反例、计算实验和形式化尝试。开始这些任务前，先读根目录 `AGENTS.md`。

## 研究循环

数学研究按以下循环推进：

```text
发散想法 -> 选择路线 -> 深入推进 -> 局部检查 -> 诊断缺口 -> 修复或回退 -> 再发散
```

公开问题也按同一流程实际求解。公开状态不降低求解优先级，也不提高候选证明的证据等级。

## 搜索承诺与证据判断

开始长跑前必须区分“要求搜索什么”和“目前已经知道什么”。项目可选择：

- `affirmative-proof`：把“存在完整肯定证明”作为搜索过程的工作假定，完整肯定证明是
  预期完成目标。普通失败、公开状态、若干结构性 gap 或现有方法族耗尽都不能终止长跑；
  必须继续生成新的表述、不变量、分解或构造。
- `counterexample`：以严格否定主命题的反例为预期完成目标。
- `either`：肯定证明或决定性反例均为预期目标。

`affirmative-proof` 是持续搜索的操作性承诺，不是数学证据，主命题仍标为 `conjecture`。
它允许探索时大胆假定目标为真并反向寻找必要结构，但所有由此得到的推导仍须逐步证明。
反例候选不能被压掉：对子引理的反例用于淘汰路线；对主命题的反例必须完整记录并进入
认证。若主命题反例严格成立，它在逻辑上推翻工作假定，应触发人工复核，而不是继续制造
肯定证明。

搜索承诺只控制全局终点，不取消回合交付。每个有边界回合仍须保存严格中间结果、失败
证书和下一轮动作。这样既能持续长跑，也不会因超时或中断丢失研究状态。

## 信息模式与来源隔离

开始研究前必须在 `progress.md` 标明本轮信息模式：

- `offline`：不访问公共互联网、已连接数据源或新增外部资料。允许读取正式题目、定义、
  本项目中明确标为内部生成的证明与计算，以及本轮专门提供的问题包。不得把记忆中的
  外部定理当作已核验事实；不得宣称结果新颖或问题开放。
- `connected`：可以按本文件的文献协议联网核查。外部材料只提供线索或可引用的定理，
  不能替代当前证明中的逻辑缺口。
- `staged`：先进行若干 `offline` 发散回合，冻结内部路线快照，再切换到 `connected`
  做文献核查和交叉验证。切换时间、原因和受外部信息影响的节点必须记录。

“来源隔离”和“路线隔离”是两件事。离线回合仍可读取本项目的长期状态；若需要真正
独立的重新发现，应给探索者只读的盲问题包，其中只含正式陈述、定义、允许的基础事实
和输出格式，不含既有路线、失败记录、当前热门方法或文献结论。共享文件系统不是安全
隔离边界，因此隔离依靠明确的允许读取清单、分离的分支产物目录和综合前不互读结果。

每条实质结论和路线至少标记一个来源：`internal-offline`、`provided-source`、
`web-source` 或 `mixed`。来源标签不改变证据等级，但使后续能够区分独立发现与受文献
影响的推导。

## 动态多智能体搜索

研究者要求多智能体长跑且编排能力可用时，由根 Agent 动态管理搜索，不预先固定“某
策略分配若干 Agent”的永久分工：

1. 第一轮向多个探索者发送相互独立的盲问题包，要求返回具体引理、构造、方程、反例或
   精确 gap；拒绝只有状态、乐观判断或把关键步骤称为“常规”的报告。
2. 根 Agent 在 `ideas.md` 维护方法族登记表。按核心数学机制归族，而不是按措辞归族；
   记录每族的表示、关键不变量、决定性子目标、证伪测试、当前障碍和重开条件。
3. 若多个探索者落入同一方法族，保留推进最深或机制真正不同的分支，把其余探索者改派
   到覆盖不足的方法族。分配依据是信息增益和具体进展，不是平均票数。
4. 在各路线暴露真实优势和缺陷之前保持若干不兼容路线；之后才允许定向交叉融合，并在
   登记表中记录父路线和新增机制。
5. 始终保留对抗审计。候选证明的审计者原则上只接收正式陈述、定义、候选证明和依赖
   清单，不接收发现过程中的说服性叙事；审计结果必须定位到具体步骤。
6. `affirmative-proof` 模式中，已登记方法族全部阻塞后先进入再发散轮次，不立即宣布
   全局阻塞。每个再发散轮次必须主动改变表示或核心机制；出现新机制时重置停滞计数。

根 Agent 是唯一同步共享 `ideas.md`、`progress.md`、`research-tree.md`、`proof-map.md`
和 `verification-ledger.md` 的角色。探索者写入
`notes/branches/<round>/<branch-id>/RESULT.md` 等各自独立的分支产物，避免并发覆盖；
盲问题包使用 `templates/blind-research-packet.md`。

## 第一阶段：定义与文献

开始证明或套用外部结果前：

1. 写清对象、量词、假设、归一化和目标。
2. 审计同名概念是否存在不同定义。
3. `connected` 回合搜索原始论文、期刊版本、arXiv、MathOverflow 和 Google Scholar；
   Wikipedia 只作术语导航。`offline` 回合跳过此步，并记录尚待联网核查的外部断言。
4. 关键文献必须读定理原文、定义上下文、全部假设和证明思路，不能只读摘要。
5. 分析相近结果为什么不能直接解决当前问题，以及额外假设在证明中起什么作用。

每篇关键文献在项目的 `references.md` 中记录：

- 题名、作者、年份；
- DOI、arXiv 或稳定链接；
- 阅读状态；
- 相关定义和归一化；
- 相关定理的完整陈述；
- 额外假设；
- 与当前问题的适用性；
- 可借鉴的技术。

文献核查未完成前，不宣称结果全新或问题开放。

## 第二阶段：例子、反例和想法

从最小和高度对称的例子开始，例如路径、圈、星、树、完全图和小规模加权图。

- 对每个脆弱中间断言主动搜索反例。
- “没有找到反例”不构成证明。
- 至少提出三个实质不同的方法族，例如直接计算、极值或归纳、谱方法、变分法、概率方法、拓扑组合方法、连续类比或计算分类。换记号、换措辞或把同一关键引理改名不算新方法族。
- 每条路线都写入 `ideas.md`，包括方法族、信息来源、暴露范围、直觉、子目标、所需结果、预计障碍、可证伪测试、状态和重开条件。

计算实验必须记录参数、随机种子、环境、复现命令和数值误差风险。实验结论只标为 `experimental`。

## 第三阶段：推进

每次选择一个想法深入推进：

1. 写出详细推导和当前依赖。
2. 每完成一个实质逻辑步骤，检查推导、隐含假设、定义、边界情形和直接反例。
3. 普通代数或记号错误立即修正，不因此放弃整条路线。
4. 在未认证引理上继续时，明确标为 `conditional`、`proof-draft` 或 GAP。
5. 适用时在 `code/` 做可复现实验，在 `lean/` 尝试形式化。

不要在未关闭的关键 gap 上继续堆叠正式下游结论。可以继续不依赖该 gap 的实验、文献核查和其他证明路线。

## 第四阶段：卡住诊断

卡住时在 `progress.md` 记录：

- 精确位置：哪一步失败；
- 类型：`gap`、`counterexample`、`circular`、`too-strong`、`definition-mismatch`、`reference-mismatch` 或 `missing-tool`；
- 详细描述；
- 暂时性还是结构性；
- 影响范围；
- 已得到的中间结果。

暂时性障碍应转化为更小的子问题。结构性障碍应把当前路线标为 `blocked`，然后换路线。
阻塞路线只有在出现新的机制、不变量、构造、额外假设或能直接攻击原 gap 的工具时才能
重开；单纯增加 Agent 数量、重复原推导或换一种表述不构成重开理由。重开时在
`ideas.md` 记录新信息和预期可证伪检查。`affirmative-proof` 长跑中，“当前已知路线全部
阻塞”不等于“所有主要路线结构性阻塞”；必须先完成项目配置要求的连续再发散轮次。
配置为 `0` 时不得因停滞自动设置全局 `blocked`，而要持续轮转、保存结果并寻找新机制；
配置为正整数时，达到门槛且仍无新机制，才向研究者报告精确停滞证书并请求方向。

同一实质障碍在 Codex 层面失败两次后，不机械重复。优先重写命题、弱化目标、寻找反例、改变方法或按升级协议申请 Rethlas。

## 第五阶段：回退和继续

回退只影响依赖错误结论的分支。未受影响的路线继续推进。

以下事件应立即更新 `research-tree.md`：

- 新增或放弃路线；
- 找到反例；
- 关键文献改变理解；
- 子目标被证明或推翻；
- verifier 返回；
- 发生回退；
- 下一主攻方向改变。

以下事件应更新 `proof-map.md`：

- 候选证明增加或删除依赖；
- 关键引理的证据等级变化；
- 最小 gap 改变；
- 某个错误影响下游结论。

## 研究树与证明依赖图

`research-tree.md` 记录发现过程，回答尝试了哪些路线、为什么分叉、哪里失败以及当前推进什么。`proof-map.md` 只记录当前候选证明的有向无环依赖图。

节点使用稳定 ID：

- `P0`：主问题；
- `A1`：攻击路线；
- `S1.1`：子目标；
- `E1`：实验；
- `C1`：反例；
- `L1`：文献结果；
- `V1`：验证事件。

边标明关系，例如 `decomposes-to`、`supports`、`refutes`、`depends-on`、`replaces`、`backtracks-to` 和 `verified-by`。

每个 proof-map 节点注明命题、来源、证据等级、对应文件和精确 gap。计算观察只能用虚线支持边，不能冒充已证明引理。图的完整模板见 `templates/research-visualization.md`。

## 验证台账

`verification-ledger.md` 登记：

- 实质中间结果；
- 完整候选证明；
- 反例；
- 关键失败；
- 证据等级变化；
- 完整十项认证结果。
- 信息来源标签以及是否由盲隔离探索独立得到。

普通代数步骤无需逐项登记十项检查。每条登记应链接到实际证据文件，并说明反例测试。重要猜想队列另有更严格的持久化规则，见 `queue-and-escalation.md`。

## 文献与联网搜索

- 优先使用英文关键词搜索。
- 技术问题优先引用原始论文、期刊官网和官方文档。
- 找到论文后读取正文，不依赖搜索摘要。
- 文献记录写入项目的 `references.md`；跨项目材料可放入 `shared/references/`。
- 引用外部定理时核对全部假设、符号和归一化。

## 代码和实验

- 代码修改后按风险运行语法检查、单元测试或实验复现。
- 尽早用真实问题做端到端检查，不只确认脚本能启动。
- 输出必须能从记录的命令复现。
- 数值结果说明精度、误差风险和边界情况。
- 代码支持数学结论时，在台账中链接脚本与输出，但证据等级仍为 `experimental`，除非另有严格证明。

## 本轮最低交付

即使主问题未解决，本轮也必须保存并报告至少一项：

- 严格中间结果；
- 精确未闭合 gap；
- 经检验的反例候选；
- 已排除路线及原因；
- 可复现实验现象；
- 已核对的关键文献差异。

只报告“问题尚未解决”不算研究推进。
