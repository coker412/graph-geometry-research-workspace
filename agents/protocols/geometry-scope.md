# Geometric objects and conventions

Use this protocol for a new problem, a change of object class, or a suspected definition mismatch. Read only relevant sections. Save settled conventions in the problem or project definitions; CURRENT_STATE keeps only essential boundaries and pointers. This file supplies checks, not mathematical theorems to cite.

## All fields

Specify object class, dimension, base field where relevant, equivalence relation, regularity, and all quantifiers. Distinguish local/global, fixed-object/uniform, existence/uniqueness, and smooth/weak conclusions. State which data constants depend on. Separate definitions from additional hypotheses.

Identically named concepts in different fields are not interchangeable. Transferring discrete curvature or a combinatorial Laplacian to smooth curvature or a differential operator requires an explicit correspondence and applicable theorem. Graph experiments are not direct evidence for a manifold statement.

## Riemannian geometry and geometric analysis

- Objects: dimension, metric regularity, boundary, compactness, completeness, connectedness, and, when needed, orientation, noncollapse, injectivity radius, or curvature bounds. Do not silently add conditions to the main problem.
- Conventions: curvature-tensor sign, Ricci/scalar contractions, Laplacian sign, volume measure, and for submanifolds the second fundamental form, trace/average convention for mean curvature, and normal orientation. Check signs on known models without forcing new conventions onto an existing project.
- Analysis: function/tensor spaces, boundary conditions, integrability, cutoffs and terms at infinity in noncompact integration by parts, maximum-principle assumptions, and regularity arguments for weak solutions.
- Variation and limits: admissible variations, fixed volume/boundary/topology, scaling, convergence topology, uniform bounds, compactness sources, and hypotheses preserved in the limit. A coordinate expression alone does not establish a global object.
- Geometric flows: initial data, time interval, gauge/diffeomorphism choices, short-time existence, and extension conditions. Distinguish finite-time singularities, normalization changes, and coordinate degeneration.
- Examples: choose Euclidean/spherical/hyperbolic models, flat tori, products, or conformal/warped families according to the hypotheses. Check noncompact ends, collapse, or degenerating sequences when relevant. State when results cover only a symmetric family.

## Discrete and graph geometry

Specify simple/multiple edges, orientation, finiteness/local finiteness, connectedness, edge weights, vertex measures, distance, Laplacian, boundary conditions, and curvature definition. Use paths, cycles, stars, trees, complete graphs, and small weighted graphs only within scope. Continuous limits require their own argument.

## Other geometric fields

Add conventions as needed without first building a discipline-wide catalog. For complex/algebraic geometry, specify base field, smoothness, compactness/properness, and analytic/algebraic category. For symplectic geometry, specify the symplectic form, boundary/infinity conditions, and allowed deformations. For metric geometry, specify length/geodesic properties, completeness, measure, and convergence. Expand only concepts actually used.
